# Luna6 首轮任务交接模板

以下模板用于下一轮有界交接；本轮实际执行记录在末尾。未冻结字段和未确定路径时不能直接作为 worker 实施指令。

## 启动条件

SWF-01 已完成，主代理核对本轮实施范围，给出 schema／CLI／错误状态、合成输入和可用运行环境；真实照片仅在当次范围明确时使用。选 `luna6-worker`（GPT-6 Luna），每轮一个 worker 与主代理并行。

## 具体任务书

- 任务：SWF-02／SWF-03，来源清单、环境只读检查和指定版本目录的纯转换。
- 项目：当前独立项目根目录（交接时由主代理提供实际绝对路径）。
- 本轮授权范围、允许读写、外部请求：由主代理填写；默认不改 NAS、数据库／应用服务、不调用额外模型 API、不安装、不提交推送。
- 契约文件、版本与 SHA：主代理填写。
- worker 唯一拥有的实际文件：主代理填写 SWF-02／SWF-03 的脚本、内部模块和相关测试完整列表，明确排除共享 schema、总入口和文档。
- 主代理同时拥有：SKILL.md、专题参考、共享契约、集成入口、运行状态和最终验收。
- 输入：主代理提供的冻结匿名计算／几何样例、来源清单及预期数量；读取旧数据用 JSON／AST，不执行历史脚本。
- 输出：约定 CLI 的来源／目录结果、可回溯缺口、相应测试和交付说明。
- 验收：原图不变，计算兼容，左右图和跨页正确，raw 字段不丢，辅助未知保留，重复转换稳定，路径边界明确。
- 遇到契约遗漏／共享文件冲突：先报告，不擅自修改共享定义；按主代理确定的新版本继续。

你不是唯一修改者。不得回退或覆盖其他人的改动，必须先看现有文件和当次任务范围。只完成本任务，运行最小相关验证；不要扩展到五册渲染、NAS 发布或数据库导入。

交付报告写明实际改动文件、实际命令与结果、缺口和未验项，并附真实 diff 范围。完成先进入“待主审”，由主代理完整差异审查和独立验证后签收。

## 2026-10-04 实际分工

同一个 luna6-worker（GPT-6 Luna）按两波执行，无重叠写入。首波拥有 collect_sources.py、check_environment.py、adapt_catalog.py、test_sources.py、test_catalog.py；主代理完整阅读交付并独立跑当时 27 项测试通过，随后要求补 entries／parent_questions 门禁。

第二波仅增加 render_packet.py、verify_packet.py、test_rendering.py 所有权；共享 API、backend、packet、workflow、发布、数学、参考文档及其余测试仍由主代理拥有。Worker 的报告作为待主审材料，最终验收记录由主代理填写；不以模型自述代替实际测试。

本轮没有委派改动 Workbench 应用、原资料、生产 NAS、模型调用、安装或提交。Git 初始化及最终本地提交由主代理执行，不 push。
