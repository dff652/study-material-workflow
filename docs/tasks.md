## SWF-01：共享契约与基线

主代理拥有 `docs/workflow-contract.md`、私有样本清单、集成选择和所有共享定义。先核对具体实施授权，不推断真实数据迁移或外发。读取所复用项目的当前接口，保存 Git 检查点、相关未提交差异与文件摘要，不能以旧评估替代源码。确定 batch／catalog／content／run／verification schema、原始 raw、来源路径与哈希规范、CLI 和退出状态；指定可调用的离线渲染接口。明确 schema 定义和公共代码路径，随后分配各 worker 文件。

冻结计算与几何的版本和样本摘要，合成测试覆盖相同格式；真实照片保存在私有工作区。开发和保留样本按整页／跨页题划分，不能将同题两页分到两边；同题重拍即使文件名／SHA 不同仍算开发内容。验收：所有后续任务有可使用的输入输出实例，数量口径、未知及失败结果明确，公开测试中无真实学习记录。没有冻结接口则 SWF-02～05 不启动依赖代码。

## SWF-02：来源工具（Luna6 首轮）

实际所有权为 `skills/study-material-workflow/scripts/collect_sources.py`、`check_environment.py` 及 `tests/test_sources.py`。扫描只限明确选择范围，保存原字节哈希、尺寸、格式、页序和问题。原图与输出根不重叠；重复准备不制造新来源。环境检查只报告解释器、依赖、字体和访问能力，不自动安装或改变服务。

验收：合成正常／损坏／超限／重复文件、路径逃逸、符号链接与输出重叠按契约处理；原图 SHA 不变；未知页序显示。照片格式支持以实际解码能力为准，不承诺任意手机格式。

## SWF-03：索引适配（同一 Luna6 首轮）

实际所有权为 `scripts/adapt_catalog.py` 及 `tests/test_catalog.py`；没有创建多余的 catalog_adapters 占位模块，不修改共享 schema 或 Workbench 的旧导入器。支持指定版本的 JSON 原索引，不执行历史 Python 读取数据。

计算斜杠引用与数字子题、几何 J3/J4/W5～W9、加号引用、左右图与名称辅助方法使用显式映射；父节点、大题和条目分别计数。主辅方法归属专题，不混合相同组号。完整题干、精确区域和独立性缺失保留。

验收：计算 81 原行逐字段保留；几何 77 原行保留，两处跨页和左右小问正确；73 大题／新增父容器分别统计；同批次重复转换结果稳定，冲突拒绝。未识别辅助方法进入待核对，不猜成已确认分类。

## SWF-04：Skill 内容（主代理并行）

主代理拥有 `SKILL.md`、`references/`、UI 元信息和内容审核规范。入口支持按范围开始或继续某阶段；专题规则和长参考按需读取。普通数学解答等相邻请求不触发完整 NAS 流程。准备知识卡、来源核对、无提示复测、家长观察模板；源内容和模型草稿的审核状态明确。

验收：另一会话可依据明确文件与状态执行，不依赖本聊天隐藏结论；所有引用存在且触发范围准确；不包含硬编码家庭数据或账号。调用策略沿用平台正常发现机制，不自行设置仅显式触发；如有实际偏好再按用户要求确定。

## SWF-05：五册及验证工具（下一轮）

共享语义、教学图契约和 renderer 选择由主代理先确定。Luna6 可拥有指定的 `render_packet.py`、`verify_packet.py`、单一离线渲染适配模块及对应测试；主代理拥有五册语义内容、数学判断和集成，不让双方同时编辑同一文件。

消除固定题目／资料版本／字体路径耦合；PDF／Word 使用同一内容快照，公式 AST、OMML、留白、图示来源和角色分别校验。独立卷使用专门输入，不从答案长文简单隐藏段落。字体源与依赖版本记录，未知字符、未支持块或溢页明确失败。

验收：两套语义回归及新内容／长内容／新字形；全部预览、图中字母、公式和留白核对；输出用途隔离；可用的 Word 实开与未验条件分别记录。不要求新批次固定为旧页数，不强求重生成 PDF 元数据字节一致。

## SWF-06：运行与入口集成（主代理）

主代理拥有运行编排入口、状态存取和引用各工具的集成代码。每阶段存精确输入摘要、输出摘要和审核／验证依据；前置变化使下游失效，不能用旧 pass。中断后核对已有文件继续，成功重放不覆盖旧版本；失败清理仅属于本次的临时数据。

验收：模拟读取、编排、渲染失败和中断；改变题干／图示／字体后拒绝旧验收；重复运行及多个独立批次隔离正确。先 `quick_validate` 做 skill 结构核对，再按行为验收；验证器成功不等于流程已通过。

## SWF-07：主代理签收

审查完整实际 diff、新增／删除文件及共享契约，独立运行必要测试，阅读正式五册和所有 PDF 页，独立核算全部新编复测答案。真实样本与金样本计数、来源、未知状态和用途核对；保留样本验证新资料。用户授权且资源足够时，可由有界 reviewer 做独立行为复核，但不替代主代理签收。

验收记录包含代码／输入检查点、环境、实际命令与结果、逐页审查、未验项、输出位置和恢复点。任何 fail 或核心未验不得宣布 v1 可用。通过后再决定本机发现／安装及分发范围，避免未验 skill 提前进入常用环境。

## 已实现工具的接入边界与后续验收

SWF-08 的 export_workbench 已实现纯导出及序列化往返检查。实际计算导出通过，完整几何因未映射辅方法拒绝而不删 raw；几何左右／跨页合成输入通过。正式接入仍需确认全部映射，再沿用 Workbench 稳定身份、追加修订、角色权限和学习历史；离线输入不自动成为已审核题库。涉及应用文件或数据库时重新划定所有权，并验证重复导入和联合恢复。

SWF-09 的 publish_packet 已实现独立交付 receipt、暂存、文件集合与 SHA 校验、原子版本目录、索引顺序、幂等和冲突拒绝。本地合成版本已真实交付两次；索引缺失修复及外来索引拒绝已测试。未来实际 SSH／NAS 仍需目标访问、断线和远端全字节验收；本轮未向生产写入。发布与删除区分，原始资料与无关历史保持。

SWF-10 的 benchmark 已实现冻结文件比较，未执行模型调用，未提供真实用量时费用为 null。bundle_packet 完成成果 ZIP 全成员校验；Git 源码分发包不含私有资料。真实供应商／OCR、发送范围及预算确定后，测开发集再冻结整页／跨页保留集，分别记录识别、分类、解析、知识、评价、变式、人工修订和真实费用。项目发现链接不等于新会话路由已验；全局安装、插件包装、真实办公客户端和家庭复测仍按实际需要验收。

SWF-11 保留首次实现提交，不把公开首发当作必须重写历史。独立 verifier 只读审查完整待上传历史、实现、测试及文档，主代理修正实际问题并记录结论；最终核对公开边界后统一推送 main。远端可见性、默认分支及 commit SHA 与本地一致后才报告上传成功。源码上传不包括本地成果 ZIP、家庭资料或凭据，也不创建应用部署／生产 NAS 发布。

SWF-12 的 CI 使用固定 action commit、只读仓库权限和明确的 Python／字体／PDF 工具；只生成和上传本任务的匿名证据，不遍历已有家庭工作目录。验证器必须拒绝零测试、跳过和失败，不把缺字体导致的 skip 当作通过。主代理在不挂载宿主资料的独立容器中从 public GitHub 匿名 clone，创建无 system-site-packages 的新 venv，并记录来源 SHA、依赖和实际结果。正式 GitHub Actions 的结论通过对应 run 核对；本地配置或容器成功不能替代该远端运行结果。实现与本地验收先 review，再统一 push。
