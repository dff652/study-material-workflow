## 保留样本准入 SOP

1. 冻结开发输入的原字节 SHA、书册／页序／原题号与题干范围。来源不只是一组文件名。
2. 在用户指定根目录内按文件名筛选，只对选定文件取得私有原字节，核对远端／本地 SHA 与解码结果，保留选择清单及缺页信息。
3. 同时检查字节和题目内容重叠。重拍、旋转、裁切、改名的同一练习页仍是同题；不能仅凭不同 SHA 宣布“未见”。跨页题整体归属一侧。
4. 读完整选定页并建立 reading ledger，保留完整题干、条件、子问、来源和观察。精确区域缺失时留整图引用及 gap；印刷页码未露出则用页序。只能报告所选可见范围。
5. 选匹配 profile；新专题使用独立 namespace 和分类修订。六组之外的不同体系需要相应契约修订，不硬塞成已有类型。知识补充与原图理论分开标注。
6. 编排五册，独立编题并核对多解、唯一性、最小性和全部答案。对照原图进行内容审查；机器成功不纠正转录错误。发现差异创建新修订，保留旧草稿。
7. render／verify 后查看每一页。缺字错误应修改表达、使用已支持公式 AST 或明确回退，不能屏蔽字体失败或缩字号掩盖问题。review 绑定最终 packet／recipe。
8. 明确代理审查、家庭批准、Word 实开和远端交付各自状态；交接及后续入口见 [Word 验收 SOP](word-client-acceptance.md)。

本轮两张候选计算照片虽然新文件名与哈希均不同，内容仍为开发时的同一组练习页，因此拒绝作为保留集，另选未参与开发的数论三页。原题某个上标的初稿本是正确的，随后一次复核误读并导致错误订正；独立 verifier 通过未缩放原图局部确认，v2 判为 FAIL，另生成 v3 并重审全部18页及数学。多个代理的相同意见也不能代替原始像素；“式子能算通”不足以证明读对照片。这两类失败均保留私有记录，没有计作通过。

## 新会话 Skill 行为 SOP

项目 `.agents/skills/study-material-workflow` 为仓库内 symlink，指向实际 skill。Codex 的项目目录发现、symlink 与显式／隐式使用机制依据 [官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。本轮检查实际会话行为，不从路径存在推断匹配成功。

使用 Codex CLI 0.159.2，仓库为 cwd，逐例启动 `codex exec --ephemeral`，不 resume／fork；每个进程禁用记忆、其他代理和相关 MCP，不更改全局配置。默认模型沿用本机配置。保存 prompt、JSON events、最终结构结果和基线 SHA。

| 场景 | 请求与实际行为 | 检查依据 |
| --- | --- | --- |
| 隐式匹配 | 请求两张匿名图片到五册，未在请求中点名 skill；会话实际读取入口及相关参考，只准备计划 | 8 条完成命令均退出 0；入口输出包含实际正文；未生成新成果 |
| 相邻普通数学 | 解释分数恒等式及抵消，直接解答 | used_skill=null；0 条执行命令；不启动完整资料流程 |
| 显式继续 | 用 `$study-material-workflow` 从已有 run.json 检查 | 11 条完成命令均退出 0；环境与 status 通过，阶段仍 machine_verified；human_review_approved=false |
| 新增专题 | 数论照片到五册的只读准备请求，未点名 skill | 7 条完成命令均退出 0；实际匹配并读取新增数论参考／profile；未提供照片时保留题干和作答未知 |

四例 thread ID 各不相同，主代理审查实际命令与输出；匿名目录运行前后全部 37 个文件的集合及 SHA 完全一致，包括 run 和审核记录，没有制造新 pass。新增专题请求验证当前入口修订，不要求读取无关计算／几何参考。

最初 read-only sandbox 在嵌套环境被 bwrap 的 loopback 初始化拒绝，该次不计通过。随后采用与父任务一致的 danger-full-access 进程环境，以提示限定只读范围并审查实际命令及前后字节；没有修改宿主安全配置。因此本轮证明的是该明确执行环境内的行为，不能宣称 read-only sandbox 或所有客户端均通过。

行为验收后若只改专题入口，可补测该专题的实际匹配与参考读取；若描述、发现路径或运行契约变化，重测相应场景。正常工具 status 不自动批准人工审核，也不凭已有 review 推进阶段。
