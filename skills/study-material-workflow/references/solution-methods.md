# 讲义解法的选择与编写

用于本项目逐题解析中的“本讲的方法／其他方法”编写和修订。生成、来源、版本与交付仍按 [逐题解析SOP](solution-companion.md)；本文不扩展五册任务或通用输入契约，不包含家庭原图与完整题目。

## 判断知识归属

先读本讲理论页，再读完整题面与图形。记录知识的讲次、真实页码或来源文件、条件及与本题的关系；页码或知识归属未知时明确待核，不编造出处。

| 依据 | 文档中的归属 |
| --- | --- |
| 本讲理论给出的模型、公式及其直接推论 | 本讲的方法；写明模型条件与推论依据 |
| 明确说明的基础性质，或本讲承接的先前知识 | 可用于本讲方法，注明“基础”或“承接某讲”，补齐需要的理由 |
| 额外采用的先前／后续讲义模型、补充定理、坐标或程序核验 | 其他方法；注明出处、先修条件和实际收益 |
| 只知道结果，或无法确认知识出处 | 保留待核；不能把答案相同写成使用了本讲知识 |

“本讲教过”与“孩子已经独立掌握”分别记录。课堂笔迹、源图上的答案和代理解答不提供独立掌握证据。

## 每题的编写框架

沿用本项目当前约定，逐题解析默认先列本讲方法，再列有益的其他方法；用户另有组织要求时按其请求调整。无第二法收益时写明无需另列，不强凑两套推导。

1. **题面与图形**：完整条件、小问、单位、原题来源；新辅助字母及其交点单独说明。
2. **本讲的方法**：所用知识及来源；“先想什么”；辅助线或代数变形的目的；条件、关系、逐步推导；全部答案。
3. **其他方法**：知识归属、所需前提和用途；给出足够复现的推导。同源换元写为“同源迁移”，逐项计算／程序枚举写为“核验”，不伪称更优解法。
4. **检查与易错点**：检查原条件、首尾项、单位及面积分割；指出本题实际容易混淆的位置。删除无帮助的套话。

主解优先选择在本讲知识下可解释、步骤连贯且不依赖额外定理的路线。更短的高级解法可以列入其他方法；“更好”应具体说明减少了哪些计算、辅助构造或容易出错的环节，而非只比较字数。

## 几何：把面积关系说清楚

先写清为何加线、延长线或补形，再对应等底等高、拼补、风筝／蝴蝶、相似或中位线的条件。三角形中位线与梯形中位线、第一讲与后续讲的相似方法分别归属，不因同属几何就混为本讲模型。

若答案与另一个三角形面积相等，优先给出结构理由：同底且顶点在与底平行的线上，所以等高；或两个等面积整体分别由共同部分和剩余部分组成，减去共同部分后剩余面积相等。抽象地说，若两种已证明的拼法满足 U=T+X、V=T+Y 且 U=V，则 X=Y。拼接区域须实际对应原图，不能只因数字相等就写“恰好相等”。

面积相等不自动推出形状相同、全等或相似；模型名也不能代替适用条件的证明。若用本讲风筝／蝴蝶关系推线段比例，先解释面积比与平行、等高的联系，再用于求高或分块；后续相似法另列。

### 阴影边界与重绘

在原始分辨率及必要细节中沿阴影外边界逐段走完，核对每条实际画线、交点和全部阴影区域。边界字母应定义为具体交点；内部线和外边界分别记录，不沿用旧示意中的点名来猜原图。

确认边界后才写面积分割、重绘和坐标核验。即使精确计算通过，也只证明所选构造内部一致；还要单独签收它与原照片一致。若漏掉一块阴影，需同时更正图、推导、答案及各组织版本，并追加旧整题签收撤销；保存旧字节和更正提示。细节仍不足以确定时保留未知，不凑一个总面积。

## 计算：先解释变形与抵消

长表达式先找共同部分、相同因子或重复尾部，保留原括号和嵌套层次。写清变形的目的与成立条件，再给公式；有限序列的预期规律与所有可能规律区分，不从有限枚举声称一般命题已经证明。

### 裂项中的系数和端点

对相差 d 的因子，先通分：

`1/k − 1/(k+d) = d/[k(k+d)]`，所以
`1/[k(k+d)] = (1/d)(1/k − 1/(k+d))`。

d≠0，两个分母均非零；不能把公差1的系数直接用于其他公差。连加时展开足够的首尾项，标明真正未抵消的项。

对连续两因子乘积求和，可构造前后相邻的三因子乘积，因为它们有共同因子 k(k+1)：

`k(k+1)(k+2) − (k−1)k(k+1) = k(k+1)[(k+2)−(k−1)] = 3k(k+1)`。

先解释“为何乘上相邻因子”，提取共同因子后再除以3。对 k=1…n、n为正整数，相邻项抵消后只留下末项 n(n+1)(n+2) 与首项 0×1×2，因此总和为 `n(n+1)(n+2)/3`。

连续三因子乘积则使用相邻四因子乘积：

`k(k+1)(k+2)(k+3) − (k−1)k(k+1)(k+2) = k(k+1)(k+2)[(k+3)−(k−1)] = 4k(k+1)(k+2)`。

同样对 k=1…n 求和，首项为0×1×2×3，末项为 n(n+1)(n+2)(n+3)，总和为 `n(n+1)(n+2)(n+3)/4`。两因子的1/3与三因子的1/4来自不同乘积差，遇到印刷公式错误应按原式验证并留下勘误，不能统一替换系数。

## 使用现有内容块与验收

方法分类是当前编写约定，通用schema仍为`swf.solution-companion.v1`。沿用题目的有序`source_refs`、`pages`、`parts`、`unknowns`和`corrections`；知识出处与方法说明写入现有文字块，不新增未经契约允许的`methods`、`primary_knowledge`或`alternative_steps`字段。私有作者台账中的同名信息不是通用CLI输入。

用`h`块表示两个方法标题，`small`块表示知识出处，`key`／`p`块承载观察点与推导；实际推导使用`method`角色。每个已知叶子的标签、答案、已知单位须一起出现在同一个`answer`角色文字块中，不同叶子可以使用不同答案块，不能只写在parts或目录。完整题面继续使用`question`角色。`source_refs`记录题目来源，不用它冒充知识出处；知识出处写入方法正文。现有`method`角色不能机读区分两类方法，若以后要按方法结构筛选或交叉链接，另开版本化契约设计。一般输入与资源条件见逐题SOP及项目冻结契约。

文字保持可编辑，必要时使用已有math AST生成OMML；不把纯文字上标宣称为公式对象。短方法尽量完整放在同页，标题与开头步骤相连，避免仅一句提示或重复说明占用续页；题面图须仍可读。所有逐题、分讲、汇总版本来自同一内容快照。

签收分别记录知识来源与题面、完整证明与答案、原图边界、文档结构、全部独有正文和目录、独立复核实际范围及两端Word。重复正文有逐页一致证据后可复用视觉结论。PC／macOS Word未实开仍not_tested；数学正确、PDF通过及NAS副本不代替学习效果或客户端验收。
